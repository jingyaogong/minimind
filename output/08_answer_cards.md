## Q1 · 为什么 MiniMind 是 toy，你为什么还用它？

**先说**：因为我要回答的不是「64M 能做到多强」，而是「reward 上升是否代表能力上升」——这是个方法论问题，小模型反而更容易做干净。

展开：
- toy 的判据我说得很清楚：63.91M 参数、2000 题训练集、held-out greedy 0.373，能力上不了台面，结论不能外推。
- 用它换来三件事：① rollout / 组内 advantage / KL / mask 全是可读可改的代码，工业框架里这些是黑盒；② 单卡 4090、1000 步 ≈ 20 分钟，我能做 6 个臂 + 1 个重跑对照 + 噪声地板实测；③ 正因为便宜，我敢把「负结果」跑到底。
- 我最后交付的是：RM 奖励 hacking 的完整证据链、长度惩罚 no-op、重跑不可复现、CoT 模板瓶颈——这些结论的价值不依赖参数量。

危险回答：「资源不够只能用小的」「大模型我也做过」。
追问预判：那你的结论对大模型有什么用？→ 回 Q14：结论是「方法学结论 + 边界声明」，不是能力结论。

## Q2 · 为什么 rule verifier 比 RM 更适合数学 RLVR？

**先说**：因为数学有可判定的 ground truth，奖励可以和任务正确性**同构**，而 RM 只是个会被人优化的代理。

展开：
- RM 的代理误差就是 hacking 面：它奖励「看起来像好答案」的表面特征。我的 RM 载入自检里，一个错误答案（`答案是 999`）拿到 **+0.632**，而完全拒答（`我不知道`）是 −2.863；训练后 reward +0.327 而正确率 −0.208。
- 规则 verifier 的代价同样要说清：只覆盖可判定域（数学/代码/结构化输出），对开放性、风格、安全无效；规则自身也可能假阳（所以我配了单测 + 人工审计）。
- 工程代价：规则信号稀疏（三态 0/1），组内经常全对或全错 → 才有了 ACR 统计、动态采样这些配套手段。

危险回答：「RM 就是不行」——RM 在偏好对齐、风格、安全上不可替代；我反对的只是「把 RM 单独当作数学正确性奖励」。
追问预判：那 RM 什么时候该用？→ 无 ground truth 的目标（偏好、风格、安全性）；或在有 rule gate 的前提下做辅助信号。

## Q3 · reward 和 accuracy 为什么可能背离？

**先说**：因为 reward 是标量代理，只要它里面有与正确性无关的分量，优化压力就会先去点那个更便宜的分量。

展开（四层，从机制到统计）：
1. **组成错位**：RM 臂的奖励是 `0.5·长度 + 1.0·think + 0.25·单标签 − 重复惩罚 + RM 分(±3)`，**没有任何一项依赖答案是否正确**。
2. **易得项优先**：格式是 0/1、学起来快；算术要真算。策略先学会外壳，再放弃内容。
3. **分布差异**：训练集与 held-out 难度分布不同（我的 medium 档比 hard 档还难，标签本身不可信）。
4. **统计假象**：单次运行的噪声就够大（同命令重跑 ±2~±6 逐题翻转），很多「提升」其实在地板内。

实证：RM 臂 reward 1.684→2.011 与**同一批 rollout** 上 verifier 正确率 0.233→0.025 同时反向——不是评估集差异能解释的。

危险回答：只答「过拟合」；要说清是奖励函数的哪一项在起作用。

## Q4 · GRPO 的 group mean/std 在全对组、全错组时发生什么？

**先说**：组内优势 `A_i = (r_i − mean(r)) / std(r)`；全对或全错时所有 r_i 相同 → 组内优势恒为 0。

展开：
- 全对/全错 → `r_i − mean = 0` → 该 prompt 对 policy gradient 的贡献为 0（除 KL / 正则项）；
- `std = 0` 时如果不做保护会除零；实现上要么加 eps，要么跳过该组；
- 代价是白烧算力（每组 6 条 rollout 全部浪费）；
- 我的监控口径：`valid_groups`（组内既有对又有错）+ `filtered_fraction`（被过滤比例），训练日志里平均约一半组是退化的。

危险回答：说「没梯度」——见 Q5，这句话不严谨。
追问预判：怎么减少？→ 动态采样（过滤/重采）、提高温度多样性、改 reward 使其在组内有区分度（如分档给不同分数）、用 DAPO 式的样本级筛选。

## Q5 · ACR 统计的是什么，为什么不能简单说「无梯度」？

**先说**：ACR 统计的是**退化组比例**——全对 / 全错组占多少，也就是有多少比例的 prompt 真的提供了学习信号。

展开：
- 准确表述是「在标准 GRPO 的组内优势口径下，该 prompt 的优势为 0」，不能笼统说「没有梯度」：
  - KL / 熵正则项仍然在反传；
  - 如果实现用 batch 级或全局归一化，该样本仍影响 mean/std；
  - 如果奖励里还有格式 / 长度这类组内非常数的项，优势并不为 0（我的 RM 臂正是如此）。
- 我的观测：rule 臂训练末期 `ACR wrong = 0.5`，RM 臂是 **1.000**（所有组全错，advantage 归零，训练已经空转）。

危险回答：「全错组没梯度所以没影响」——它影响的是有效样本量、吞吐和统计口径。

## Q6 · 为什么正式 run 要显式 `loss_type=grpo`？

**先说**：因为默认值是隐式的第二配置源，实验可复现性要求「命令 = config = 日志」三者一致。

展开：
- 上游 trainer 有多个 loss 分支，不同分支的数据要求、归一化、KL 估计方式都不同；
- GRPO 社区实现差异很大（是否 std 归一、KL 形式、是否过滤退化组）——不写明就无法复现和跨臂比较；
- 我用 `scripts/experiment_registry.py` 从预注册表渲染命令，显式参数保证 8 个 run 除自变量外逐字一致；
- 实操风险：写错/漏写会跑到别的分支（例如偏好类 loss 直接因数据格式不匹配崩掉），白烧 GPU。

危险回答：「反正默认就是 GRPO」——这正是审计要防的隐性配置。

## Q7 · 你如何避免 `1` 被错误地从 `21` 中 substring 命中？

**先说**：不做子串匹配，先切段、再定位标记、最后用带边界的正则抽数字。

展开：
1. 先用 `</think>` 把输出切成最后一段（只认最终答案区）；
2. 只在含标记（`答案是`）的那一行取候选；
3. 用边界正则 `(?<![\d.])(-?\d+(?:\.\d+)?)(?![\d])` 或对整串 `fullmatch`，杜绝 `21` 命中 `1`；
4. 归一化：全角数字、千分位逗号、末尾句号；
5. 单测覆盖：`21`、`1`、`21 和 1`、`-5`、`1.0`、`1,000`；
6. 更关键的是**同一份抽取函数**被数据生成、训练奖励、评估三处共用——口径漂移比单点 bug 更致命（我们踩过：评估侧曾把 marker 放宽，差点让数字失真）。

危险回答：「我用 `if '1' in text`」——面试官就是在等这个。

## Q8 · verifier 假阳和假阴哪个更危险？如何测试？

**先说**：假阳更危险——它给错误行为发正奖励，等于主动教坏模型。

展开：
- 假阳（判错为对）：RL 语境下是「错误行为被强化」，且没有任何纠错信号；no_answer 至少不会被奖励。
- 假阴（判对为错）：损失一个正样本，训练慢一点、偏保守，不至于教坏。
- 顺带说清我的分档设计（`reward_tier`，`--verdict_tier binary`）：correct = +1.0、incorrect = 0.0、no_answer = **−0.5**——「不答」比「答错」罚得更重，否则模型会学会用沉默规避错误答案。
- 测试手段：① 边界单测（Q7 那组）；② 人工审计抽样（我做了 50 条 sample + 每类 20 条原文审计）；③ 对抗构造（等价表达式、单位、负号、千分位）；④ 建混淆矩阵并**把假阳率当回归指标**持续跟踪。
- 我的间接证据说明假阳的破坏力：RM 给一个错误答案（`答案是 999`）+0.632，训练后 86.8% 输出是纯算术错误而 reward 仍上升。

危险回答：只答「都要避免」——要有优先级和量化方案。

## Q9 · pass@1 和 greedy 有什么区别？pass@16 成本如何控制？

**先说**：greedy 是「最自信路径」，pass@1 是「随机采样一次的期望成功率」；两者的差反映分布形态。

展开：
- greedy：温度 0、取 argmax，1 次生成；我测到 0.3725。
- pass@1：温度 0.8 采样，n 次采样用无偏估计（k=1 时就是 c/n）；我测到 0.3113。greedy > pass@1 说明贪心路径优于平均采样——分布不是平的，采样会分散到差路径。
- pass@16：16 次里至少一次正确，衡量「能力存在性」；我测到 0.5525，而四个 RL 臂对它的净变只有 ±10 题以内且不显著 → 支持「分布锐化、能力不扩展」。
- 成本控制：① 16 采样只跑 400 题 held-out（6400 次生成），训练侧不跑；② greedy 先出结论，再决定要不要补 pass@k；③ 限制 `max_new_tokens`、批量采样、复用模型加载；④ **先算功效**——我的效应量落在噪声地板内，评估后主动放弃把 400 扩到 500，因为只会收窄 CI、不会改变结论。

危险回答：「pass@16 更好所以都用 16」——成本和口径要一起谈。

## Q10 · Qwen / TRL / verl 的 rollout、policy logprob、reference logprob 如何对齐？

**先说**：这一层我没有实操，是我明确标注的能力边界；原理上对齐的关键是「同一 token 序列 + 同一模板 + 同一精度口径」。

展开（若被追问原理）：
1. tokenizer 与 chat template 必须一致，否则 token 序列不同，logprob 没有可比性；
2. **不重新编码**：用 rollout 产生的 `input_ids` 重算 logprob，避免 encode/decode 往返漂移；
3. mask 正确：prompt 段与 padding 段不参与 loss，只对 completion 段算；
4. 一致性检查：`exp(logp_policy − logp_rollout)` 的 importance ratio 应 ≈1，偏离大说明 kernel/精度（bf16 推理 vs fp32 logits）或模板不一致；
5. reference logprob 用冻结模型、同一批 token、eval 模式计算，KL 才对得上。

我在 MiniMind 侧做的是同源版本：rollout 与 policy 是同一个模型对象和 tokenizer，天然对齐；reference 是冻结副本，KL 用同一批 token 的 logprob 差。

危险回答：不懂装懂说「verl 里对齐很简单」——被追问 kernel 差异就崩了。

## Q11 · 为什么 mix reward 要先标准化？

**先说**：因为 rule 分（−0.5/0/1）和 RM 分（实测 1.68~2.61）量纲差几倍，不标准化时 α/β 没有可解释含义，等于让 RM 主导。

展开：
- 组内 z-score 后每项均值 0、std 1，α=β=0.5 才真的是「等权」；
- 副作用我如实记录：① 该臂 reward 均值恒为 0，从 reward 绝对值读不出趋势（我的汇总脚本一度把它读成「奖励没动」，是仪器缺陷，已修）；② 标准化改变 rule 分量形态（全对组被抹平），所以我无法把「RM 污染」与「标准化副作用」完全分离——这是报告里写明的局限；
- 替代方案：固定常数缩放（保留绝对水平）、rule 做 gate（只在 rule 无区分度时用 RM）。

危险回答：只说「为了统一量纲」——要说出副作用与你为什么仍接受它。

## Q12 · 如果 reward 涨了但 held-out 不涨，你会先查什么？

**先说**：先拆 reward 组成，再看同一批 rollout 上的 verifier 正确率有没有一起动——这是最省时间的一步。

展开（六步）：
1. **拆奖励**：哪个分项在涨（我这里是 RM 分 + 格式项，与正确性无关）；
2. **并排看训练侧正确率**：rule 臂 reward +0.225 与 correct +0.225 同步；RM 臂 +0.327 vs −0.208 背离 → 立刻锁定奖励函数；
3. **查假阳**：人工审计 + 抽样（「格式漂亮但算错」拿高分）；
4. **查评测一致性**：训练/held-out 分布、模板、难度标定（我撞上 medium 档比 hard 档更难 → 人工标签不可信）；
5. **查统计可信度**：同批题配对检验 + 噪声地板（同命令同种子重跑）；
6. **查易得项**：长度 / 格式 / 重复是否在变。

我的实测结论：训练侧正确率 0.317→0.542 是真涨，但 held-out 只 +0.02 且不显著 → 是过拟合训练分布 + 噪声，不是「RL 有效」。

危险回答：「先调学习率」——先分清是奖励问题、评测问题还是统计问题。

## Q13 · 为什么不直接做 OPD、PRM 或 Agentic RL？

**先说**：这三者都建立在「reward 可信 + 评测可信」之上，我先把地基做干净。

展开：
- **OPD**（on-policy distillation）：需要强教师和稳定蒸馏目标；在没搞清楚「reward 是否代表学习」之前做，结果无法归因。
- **PRM**（过程奖励）：需要步骤级标注，成本与假阳风险更高；我已定位主要失败模式是「模板续写 + 算术执行错误」，PRM 可能有效，但前提是先有可靠的步骤切分与标注协议。
- **Agentic RL**：需要环境/工具链与长程 credit assignment，和「可判定答案」的设定不是一条线。
- 我的取舍是：无泄漏数据、三态 verifier、配对统计、噪声地板这四件先立住，上层方法才有意义——否则任何提升都可能是仪器噪声。
- 如果继续：先做 PRM 的步骤级标注小实验，或用 rule gate 改进 mix。

危险回答：「因为太难/没资源」——要说清依赖关系。

## Q14 · 你的结果能否证明「RL 学会了新推理能力」？

**先说**：不能，而且我在报告里把这句话直接列为「不能推出的结论」。

展开（三条理由）：
1. **能力指标不显著**：pass@16 逐题净变 +2 / +10 / −2 / +2（p 0.14~0.87）；greedy 净 +6~+9（p 0.06~0.18）——都过不了 0.05。
2. **越过不了噪声地板**：同命令同种子重跑就能产生 ±2 greedy 净变、−6 能力净变、200 个记录点只有 35 个一致。四个臂的全部效应都落在这个地板内 → 只能算方向性证据。
3. **规模边界**：63.91M + 2000 题 + 单卡，不能外推。

能证明的四件事：RM 单独作数学奖励会内容层 hacking（p<1e-4）；长度惩罚是 no-op；CoT 模板是 RL 之前的瓶颈（0/20 → 0.373）；单臂单次运行不足以支撑结论。

危险回答：「提升了准确率就说明学会了推理」——这正是本项目的靶子。

# 高危补充题

## B1 · 你的 SFT 冷启动做了什么？为什么说 CoT 模板是瓶颈？

250 步、2000 条，唯一变量是 CoT 模板：v1 只写「结果是 N」→ held-out 0/20（greedy 0.000）；v2 改成列竖式分步 → 0.373。说明 RL 之前模板就已经决定上限，RL 只会放大已有的模式（探索性结论，单变量、非预注册）。

## B2 · KL 系数 β=0.1 怎么定的？

沿用 SOP 预设值，**没有做 β 扫描**——这是局限，我如实写。如果要扫：看 KL 曲线（是否爆炸/塌缩）与 held-out 的折衷，固定其他变量，β ∈ {0.01, 0.1, 0.5}，并注意要用配对检验判断差异。

## B3 · 训练 GPU 利用率只有 36%，你怎么解释？

瓶颈在 CPU 单核：`batch_size=2 × G=6` 的自回归生成是逐 token 的，`num_workers=0`，采样/解码在 CPU 侧排队；显存只用了 7.2 GB。优化方向：加大 batch、开多 worker、换 vLLM 类推理引擎、降低 `max_gen_len`；但当时优先保证与预注册命令一致，没有中途改配置。

## B4 · 语音方向你没做过，为什么投？

坦白 + 两个动作：① 迁移面——训练调优闭环、数据工具、评测与 bad case 定位是通用的，我的项目正好一直在做这三件事；② 已做的学习动作（见 `09_upgrade_plan.md` 的半天项）：读完 1~2 篇语音交互 LLM 工作（如 Qwen-Audio / GLM-4-Voice 类）并跑通一次 ASR 或语音对话 demo，能讲清 pipeline、延迟与数据难点。不要编「做过语音」。

## B5 · 你为什么不重新标难度标签、不重跑数据？

因为预注册已冻结：事后改数据/改标签等于事后调参，结论会失去可证伪性。我把「难度标签倒挂」当作审计发现记录（medium 0.128 < hard 0.436），而不是去修数据把结果做漂亮。要改就换新 tag、重跑整链、重新签哈希。

## B6 · 如果重做一次，你会先改什么？

三件事按顺序：① 先测长度/分布再设 cap（长度惩罚的教训）；② 训练侧加确定性开关（`CUBLAS_WORKSPACE_CONFIG`）或至少把「同配置重跑」纳入常规流程，早一点知道噪声地板；③ 从第一版就记录每步的组件级 reward（mix 臂的 `component_degenerate_groups` 埋点缺失，导致一个解释无法分离）。
