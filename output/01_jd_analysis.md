# 01 · JD 分析

来源：`/Users/qi/实习/materials/target_jd.txt`（语音语言交互大模型方向）。

## JD 主线

四条职责可以归成三件事：

1. **训练调优闭环**：训练数据处理 → 模型训练与调优 → 测试结果分析与性能优化（「日常调优」）。
2. **数据 / 算法工具研发**：数据挖掘、数据增强等核心算法工具的研发，并针对大模型特性专项优化。
3. **平台化 + 前沿跟进**：NLP 能力平台化落地，跟进前沿技术。

五条要求里，真正的硬门槛是：

- 大模型研发背景，熟悉 Transformers / GLM / GPT 等主流架构；
- Linux 下的数据处理，Python / perl / C / C++ 精通其一，数据结构与算法基础扎实；
- 对 **SFT 数据敏感**、能快速定位核心问题；
- 语音交互场景有兴趣（有经验者优先）。

## Role Type

`mixed`，主线是 **LLM algorithm + post-training**，叠加 **data engineering**；领域是 **speech-language interaction**（语音交互）。

## Must-Haves 映射

| JD 要求 | 是否有证据 | 证据 / 缺口 |
|---|---|---|
| 熟悉 Transformer / GLM / GPT 架构 | **有** | 从零手写 Transformer（多头注意力 / 位置编码 / FFN）；MiniMind 全链路改造（decoder-only Transformer，含 RoPE / RMSNorm / GQA 一类的现代组件，按 `model/` 实际实现讲）；HuggingFace 生态 |
| 大模型训练与调优 | **有（小规模）** | 冷启动 SFT（250 步）→ 6 臂 GRPO 训练 → held-out 评测；loss、KL、熵、advantage、退化组全程埋点 |
| 测试结果分析与性能优化 | **强** | 400 题 × 16 采样的评估矩阵、逐题配对 McNemar、功效估算、错误类别分析（400 条全量）、噪声地板实测 |
| 数据挖掘 / 数据增强工具 | **强** | 确定性数据生成器（`scripts/clean_math_data.py`）：表达式 key 去重、难度分层、sha256 清单 + 50 条人工审计抽样；train/held-out 重叠 0 |

| Linux 数据处理 + Python 精通 | **有** | 服务器全流程（AutoDL / RTX 4090）、脚本化 pipeline、313 个单测 |
| perl / C / C++ 精通其一 | **无证据（需确认）** | 简历未写；面试若被问，如实说 Python 为主 + 课程级 C 基础，别硬答 |
| 数据结构与算法 | **部分** | 教育背景 + 脚本实现；建议面试前刷一遍数组/哈希/双指针/二分（本岗位手撕概率不低） |
| 语音交互场景兴趣 / 经验 | **缺口（最大）** | 项目与简历均无音频；这是唯一无法用现有材料覆盖的 must-have 方向项 |

## Hidden Interview Tests（JD 背后真正会考的）

1. 你说做了「模型调优」——是改 prompt，还是真的动了 loss / reward / 数据？（→ 你答得上，且能给出负结果）
2. 训练 reward 涨了，你凭什么说模型变好了？**这个岗位天天要回答这题**（→ 你的核心卖点）
3. 数据怎么来的、有没有泄漏、怎么去重、怎么分层（→ 你有）
4. 评测集多大、多少采样、显著性怎么算（→ 你有）
5. 会不会只报喜不报忧（→ 你有 RM 负结果 + 不可复现实测，这是加分项）
6. 语音方向：为什么投这个方向，了解多少（→ 需要准备，见 `09_upgrade_plan.md` 的半天项）

## Fit Verdict

**weak fit**（可投，但要用主线覆盖领域缺口）。

- 能对上的：训练调优闭环、数据分析、数据工具、Python/Linux —— 正好是职责 1 和 2。
- 对不上的：语音/音频领域经验（JD 写的是「优先」而非「必须」，属于可解释缺口）；C/C++/perl（同类岗位可能考）。
- 最高面试风险：**「你这些是 64M 玩具模型的结论，和我们要做的几百亿参数模型有什么关系？」**（答案卡第 1、14 条）
- 最快的有效升级：半天——读 1~2 个语音 LLM 相关工作 + 跑一次开源 ASR/语音对话 demo，把「有兴趣」变成「有动作」。

## Strategy

1. 简历把「数学 RLVR 训练动态审计」放在项目第一条，用**评测与负结果**做差异化，而不是堆「训练了大模型」。
2. 面试开场用 SOP §15.3 的 60 秒主线（见 `11_final_pack.md`）。
3. 主动提「规模边界」和「噪声地板」，把「诚实」变成技术判断力的证据。
4. 语音缺口不要藏：准备好「我为什么投语音 + 我打算怎么补」的两句话（`08_answer_cards.md` 补充题 B4）。
