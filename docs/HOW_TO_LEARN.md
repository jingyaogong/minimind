## 一、为什么做这套教程

minimind 主 [README](../README.md) 是一份 150KB 的"百科全书"，覆盖了从原理到实验的所有细节，非常完整 ——
但也正因为太完整，初学者一打开就会迷失在 17 万字里，不知道**今天该读哪一段、该跑哪条命令**。

这套 `docs/` 借鉴了两个优秀项目的做法：

| 参考项目 | 借鉴点 |
|---|---|
| [happy-llm](https://github.com/datawhalechina/happy-llm)（Datawhale, 32.5k⭐） | 章节式循序渐进、理论 + 实战、状态表 |
| [learn-claude-code](https://github.com/the-gigi/learn-claude-code) | Track 化路径、checkbox 复选框、即学即用 |

并叠加了**心理学持续学习技巧**，让你既能"学得进"，也能"学得完"。

## 二、背后的 10 个心理学技巧

> 你不用记，**这套教程已经把这些技巧"内嵌"到结构和措辞里了**。但你了解原理后会更配合，效果会更好。

| # | 心理学原理 | 在教程中的体现 |
|---|---|---|
| 1 | **微习惯 / 小步快走**（BJ Fogg *Tiny Habits*） | 把"训练一个 LLM"拆成 30+ 个 5 分钟可完成的小步 |
| 2 | **目标梯度效应**（Columbia, 2006） | checklist 复选框 + 进度看板，越接近终点越想完成 |
| 3 | **即时反馈**（操作性条件反射 Skinner） | 每步末尾都有 "✅ 验证" 步骤，让你立刻看到结果 |
| 4 | **自我效能感**（Bandura） | 章首"现在你能做什么"明确每章产出 |
| 5 | **主动回忆 / 测试效应**（Roediger, 2006） | 章末 "自检题" 折叠区，回忆比再读有效 2 倍 |
| 6 | **间隔重复**（艾宾浩斯遗忘曲线） | 同一概念在理论篇→实战篇→进阶篇多次以不同视角出现 |
| 7 | **心流**（Csikszentmihalyi） | 难度递进，主线流畅、进阶部分单独折叠不打扰 |
| 8 | **承诺一致性**（Cialdini *Influence*） | 让你先在 [study-tracks.md](./study-tracks.md) 写下"我打算 X 周完成" |
| 9 | **社会认同**（Cialdini） | 提示"上万人正在和你一起学"+ 社区入口 |
| 10 | **叙事传输**（Green & Brock） | 关键章节用类比/故事开场，降低抽象感 |

## 三、怎么用这套教程

### 1. 选一条 Track，**只走一条**

在 [study-tracks.md](./study-tracks.md) 里勾选你想走的 Track，**不要同时走多条**。
心理学研究表明，并行多任务会显著降低完成率。

### 2. 在每篇文档顶部先看 "TL;DR" 与 "你将能"

- **TL;DR**：30 秒看完整篇在讲什么
- **你将能**：明确做完后新增的能力（首因效应）

### 3. 顺着 **步骤号** 一行行往下做

每篇实战篇都按 `步骤 1 / 步骤 2 / ...` 编号，每个步骤末尾通常有：

```
✅ 验证：xxx 命令
预期输出：xxx
```

**不要跳过验证步骤** —— 这是即时反馈机制，跳了等于没学。

### 4. 在 checkbox 上打勾

每篇文档对应 [study-tracks.md](./study-tracks.md) 里的若干 checkbox，做完一篇就把对应项从 `[ ]` 改成 `[x]`。

> 在 GitHub / VS Code / Typora 里直接编辑 markdown 即可，commit 一下还能保留进度版本。

### 5. 章末做 "自检题"

每篇理论篇/实战篇末尾有 3-5 道**不直接给答案**的自检题（折叠区）。
**先自己想 30 秒再展开**，这是测试效应最强的方式。

### 6. 遇到问题按这个顺序找答案

1. 翻本篇的 "🧯 踩坑提示"
2. 看 [99-参考/FAQ](./99-参考/FAQ.md)
3. 查 [99-参考/术语表](./99-参考/术语表.md)
4. 回 [主 README](../README.md) 对应章节
5. 去 [minimind Issues](https://github.com/jingyaogong/minimind/issues) 搜索

## 四、推荐的硬件 / 软件配置

| 角色 | 配置 |
|---|---|
| 🐢 纯读理论 | 任何机器，CPU 都行 |
| 🚶 跑通现成模型 | 任意 GPU ≥ 8GB 显存（甚至 Mac MPS 也能跑） |
| 🏃 从 0 训练 minimind-3 | 单卡 3090 / 4090（24GB），约 2h |
| 🏋️ MoE 完整复现 | 单卡 3090 / 4090 即可（198M-A64M） |
| 🚀 多卡加速 | N 张卡，用 `torchrun --nproc_per_node N` |

软件栈：Python 3.10+ / PyTorch 2.x / CUDA 12.x / 见 [requirements.txt](../requirements.txt)。

> 远程 GPU 主机推荐：本地用 VS Code Remote-SSH 改代码，远程跑训练；用 [swanlab](https://swanlab.cn/) 看曲线，不用一直盯屏。

## 五、几条"不踩就赚"的学习心法

### 1. **不要从零造词表**
很多新手第一件事就是训练自己的 tokenizer，结果模型权重、数据格式、推理接口全部对不齐。
minimind 的 6400 词表是**经过权衡的设计**，先用它，等理解了再换。

### 2. **第一遍别读论文**
LLM 论文 90% 内容是数学推导，对入门者不仅没帮助，还会劝退。
**先跑通代码 → 看到模型说话 → 再回头读论文**，效率高 10 倍。

### 3. **改一个小数，胜过看十页讲解**
看到 `temperature=0.85`，不要问"为什么是 0.85"，**改成 0.1 和 1.5 各跑一次**，你就懂了。

### 4. **commit 每个里程碑**
当你跑出 `pretrain_768.pth` 时，commit 一下并写日志：
```
git commit -m "🎉 pretrain done, loss=2.x, 模型会接龙了"
```
未来回看自己的 progress 是巨大的动力来源。

### 5. **卡住超过 30 分钟就停下来**
不是放弃，是**去 issues / 社区问**。卡太久会消耗意志力，影响后面学习。

## 六、学习进度可视化建议

除了勾选 checkbox，还推荐：

### 方式 1：在仓库里维护 `my-progress.md`

```markdown
# 我的 MiniMind 学习记录

## 承诺：4 周内完成 T2 系统精读
- 起始日期：2026-07-30
- 目标完成：2026-08-27

## 进度
- [x] 00-起步/01-环境准备 (2026-07-30)
- [x] 00-起步/02-代码地图 (2026-07-31)
- [ ] 01-理论/02-Transformer核心架构 ← 今天
```

### 方式 2：用 swanlab 看训练曲线

```bash
cd trainer && python train_pretrain.py --use_wandb
# swanlab 会在浏览器打开实时曲线，每 100 步自动刷新
```

看到 loss 在下降就是最好的多巴胺。

### 方式 3：用 minimind 的 web_demo 给朋友看

```bash
cd scripts && streamlit run web_demo.py
```
**给真人用一下你训练的模型**，比任何鸡汤都能让你继续学下去。

## 七、给不同背景学习者的建议

| 你的背景 | 建议路径 |
|---|---|
| **完全新手**（没用过 PyTorch） | 先花 1-2 小时过 [PyTorch 60 分钟入门](https://pytorch.org/tutorials/beginner/deep_learning_60min_blitz.html)，再走 T2 |
| **会 PyTorch，没接触过 NLP** | 直接走 T2，理论篇是为你准备的 |
| **做过 NLP 但没训过 LLM** | 走 T1，把 minimind 跑通；再跳进 T3 RL 部分 |
| **会调 transformers 库，想看底层** | 走 T2 + 01-理论，重点对照 `model_minimind.py` |
| **想做产品** | T1 + T4，跑通后直接 vllm 部署 |
