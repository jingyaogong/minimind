## 二、采样参数详解

generate 实现在 `model/model_minimind.py:257-288`。每步采样流程：

```
logits = outputs.logits[:, -1, :]        # 取最后一位 logits
                    ↓
logits = logits / temperature             # 1. 温度缩放
                    ↓
if repetition_penalty != 1.0:            # 2. 重复惩罚
    对已出现 token 加惩罚
                    ↓
if top_k > 0:                             # 3. top_k 截断
    只保留前 k 个，其余设 -inf
                    ↓
if top_p < 1.0:                           # 4. top_p 截断
    排序后累计概率 > p 的设 -inf
                    ↓
probs = softmax(logits)                   # 5. 归一化为概率
                    ↓
next_token = torch.multinomial(probs, 1)  # 6. 采样
```

### 2.1 temperature（温度）

代码：`model_minimind.py:267` `logits = outputs.logits[:, -1, :] / temperature`

**作用**：把 logits 除以 temperature，控制概率分布尖锐度。

| temperature | 效果 | 适用场景 |
|---|---|---|
| 0.1 | 几乎 argmax，输出固定保守 | 代码生成、事实问答 |
| 0.85（默认） | 平衡多样性与合理性 | 通用对话 |
| 1.5 | 概率变平，更随机更"创意" | 头脑风暴、写故事 |

**对比实验**：同一问题 `解释一下什么是机器学习`，同一种子：

```bash
# A. 保守（事实问答风格）
python eval_llm.py --weight full_sft --temperature 0.1 --top_p 0.95
# 输出：机器学习是让计算机从数据中学习规律的技术...

# B. 平衡（默认，对话风格）
python eval_llm.py --weight full_sft --temperature 0.85 --top_p 0.95
# 输出：机器学习是一种 AI 方法，可以分成监督、无监督、强化学习...

# C. 创意（发散）
python eval_llm.py --weight full_sft --temperature 1.5 --top_p 0.95
# 输出：嗯，机器学习？让我想想... 简单说就是教电脑自己学会做事，比如...
```

> temperature > 1.0 会让概率分布**变平**（所有 token 概率都更接近），输出更随机。
> temperature < 1.0 让分布**变尖**（高概率 token 更高，低概率 token 更低），输出更确定。
> 当 temperature → 0 时退化为 argmax（贪婪解码）。

### 2.2 top_k（截断到前 k 个）

代码：`model_minimind.py:271-272`

```python
if top_k > 0: 
    logits[logits < torch.topk(logits, top_k)[0][..., -1, None]] = -float('inf')
```

**作用**：只在 logits 最高的 k 个 token 里采样，其他全部置 `-inf`。

| top_k | 效果 |
|---|---|
| 1 | 退化为 argmax（贪婪） |
| 50（默认但 eval_llm 未传，见下） | 限制在常见 token 内 |
| 200 | 更宽松，可能采样到罕见词 |

> 注意 `eval_llm.py:82-87` 调用 `generate` 时**没有传 top_k 参数**，走的是 `model_minimind.py:257` 的默认 `top_k=50`。

### 2.3 top_p（nucleus sampling）

代码：`model_minimind.py:273-277`

```python
if top_p < 1.0:
    sorted_logits, sorted_indices = torch.sort(logits, descending=True)
    mask = torch.cumsum(torch.softmax(sorted_logits, dim=-1), dim=-1) > top_p
    mask[..., 1:], mask[..., 0] = mask[..., :-1].clone(), 0
    logits[mask.scatter(1, sorted_indices, mask)] = -float('inf')
```

**作用**：按概率从大到小排序，累计概率达到 `p` 后剩下的全部置 `-inf`。

| top_p | 效果 |
|---|---|
| 0.1 | 非常严格，只取最高概率几个 token |
| 0.95（默认） | 平衡，常见 nucleus sampling |
| 1.0 | 不截断，纯按概率采样 |

**top_k vs top_p**：
- top_k：固定数量（前 k 个），不管概率分布
- top_p：动态数量（累计概率达 p 的最小集合），适应分布尖锐度
- 实践中通常**两者一起用**（先 top_k 再 top_p），eval_llm 默认 `top_k=50, top_p=0.95`

### 2.4 repetition_penalty（重复惩罚）

代码：`model_minimind.py:268-270`

```python
if repetition_penalty != 1.0:
    for i in range(input_ids.shape[0]):
        seen = torch.unique(input_ids[i])
        score = logits[i, seen]
        logits[i, seen] = torch.where(score > 0, score / repetition_penalty, score * repetition_penalty)
```

**作用**：对已出现 token 的 logits 做惩罚，减少重复。

| repetition_penalty | 效果 |
|---|---|
| 1.0（默认） | 不惩罚 |
| 1.1-1.3 | 适度减少重复 |
| 1.5+ | 强力惩罚，可能输出不连贯 |

> ⚠️ `eval_llm.py:86` 默认传 `repetition_penalty=1`（不惩罚）。如果输出重复严重，改 `eval_llm.py` 第 86 行把 `repetition_penalty=1` 改成 `repetition_penalty=1.1` 试试。

### 2.5 采样参数组合建议

| 场景 | temperature | top_p | repetition_penalty | 备注 |
|---|---|---|---|---|
| 事实问答 | 0.1 | 0.9 | 1.0 | 准确性优先 |
| 通用对话 | 0.85 | 0.95 | 1.0 | 默认值 |
| 创意写作 | 1.0 | 0.95 | 1.1 | 多样性 |
| 代码生成 | 0.2 | 0.9 | 1.05 | 准确 + 防重复 |
| 长文接龙（pretrain） | 0.85 | 0.95 | 1.05 | 防"我我我"式重复 |

## 三、KV cache 原理（推理为什么快）

代码：`model/model_minimind.py:111-134` Attention.forward + `257-288` generate

### 3.1 没 KV cache 时

```
已生成: [a, b, c]
要预测第 4 个 token:
  → 重新 forward([a, b, c]) 算 K/V
  → attention 时 a/b/c 之间互相 attend
  → 总计算量 O(L²)
```

### 3.2 有 KV cache 时

```
已生成: [a, b, c]，K/V 已缓存在 past_key_value
要预测第 4 个 token d:
  → 只 forward([d])  算 d 的 Q/K/V
  → d 的 K/V 拼接到缓存（model_minimind.py:121-122）
  → d 的 Q attend 到 [a,b,c,d] 的 K/V
  → 总计算量 O(L) per step
```

代码：

```python
# model_minimind.py:120-123
if past_key_value is not None:
    xk = torch.cat([past_key_value[0], xk], dim=1)   # K 拼接
    xv = torch.cat([past_key_value[1], xv], dim=1)   # V 拼接
past_kv = (xk, xv) if use_cache else None
```

generate 里每步只 forward 新 token（`model_minimind.py:264-265`）：

```python
past_len = past_key_values[0][0].shape[1] if past_key_values else 0
outputs = self.forward(input_ids[:, past_len:], ..., use_cache=True)
```

### 3.3 推理速度

代码：`eval_llm.py:81, 90-91`

```python
st = time.time()
generated_ids = model.generate(...)
gen_tokens = len(generated_ids[0]) - len(inputs["input_ids"][0])
print(f'[Speed]: {gen_tokens / (time.time() - st):.2f} tokens/s')
```

## 四、YaRN 外推：4 倍上下文

代码：`model/model_minimind.py:32-39` + `62-78`

启用：`--inference_rope_scaling`

```bash
python eval_llm.py --weight full_sft --inference_rope_scaling
```

### 4.1 为什么需要外推

模型在 `max_seq_len=768` 上训了 SFT，但**直接推理长上下文（如 4096）会乱**：
- 没见过的位置 → RoPE 频率外推 → attention 分布漂移 → 乱码

YaRN（Yet another RoPE extensioN）通过**频率缩放**让模型自适应更长上下文：

```python
# model_minimind.py:32-39
self.rope_scaling = {
    "beta_fast": 32, "beta_slow": 1, "factor": 16,
    "original_max_position_embeddings": 2048,
    "attention_factor": 1.0, "type": "yarn"
} if self.inference_rope_scaling else None
```

数学（`model_minimind.py:64-73`）：
- 把频率乘以 `(1 - γ) + γ/s`，γ 是 ramp 函数
- 高频段（依赖相对位置）不缩放
- 低频段（依赖绝对位置）大幅缩放
- factor=16，original=2048，理论外推到 32768

### 4.2 实测外推能力

```bash
# 默认（无外推）：长 prompt 可能乱
python eval_llm.py --weight full_sft --historys 20 --max_new_tokens 500

# 开 YaRN：长 prompt 更稳
python eval_llm.py --weight full_sft --inference_rope_scaling --historys 20 --max_new_tokens 500
```

> 注意：YaRN **只解决位置编码问题，不提升模型实际长文能力**（训练数据没见过的内容依然学不会）。Mini 数据训出的 Zero 模型长文能力很弱，需要完整训练 + RLAIF。

## 🧯 踩坑提示

### Q1：`ValueError: size mismatch for embed_tokens.weight`
权重名/路径不对。检查 `out/{weight}_{hidden_size}{_moe?}.pth` 是否存在，`--weight`、`--hidden_size`、`--use_moe` 要和训练时一致。

### Q2：推理输出全是乱码
- 检查 `--weight` 是不是 `pretrain`（pretrain 模型不会"回答"只会接龙）
- tokenizer 版本对不上：`pip install -r requirements.txt` 锁定版本

### Q3：长对话时崩成乱码
max_seq_len 超出训练长度。开 `--inference_rope_scaling` 或减小 `--historys`。

### Q4：输出无限重复（"我我我我"）
- 加 `repetition_penalty`（修改 `eval_llm.py:86` 的 `repetition_penalty=1` → `1.1`）
- 调低 `--temperature`（0.85 → 0.5）
- 检查 SFT 训练数据是否完整（对话不能为空）

### Q5：MoE 模型推理比 dense 慢
正常。minimind 没用 kernel-fused 算子，4 experts/top-1 native 实现比 dense 慢约 50%。要更快换 vllm。

### Q6：Mac MPS 报 `operation not implemented`
部分算子 MPS 不支持。换 `--device cpu`（慢但能跑）或换 Linux GPU。

### Q7：CLI 选 `[0] 自动测试` 输出不符合预期
预设 prompts 在 `eval_llm.py:51-60`，包含 8 个问题。模型能力有限时可能答不全。建议手动输入简单问题先测。

### Q8：`--inference_rope_scaling` 开了反而效果更差
YaRN 是为长上下文设计的。短对话（< 训练 max_seq_len）开它**反而引入分布漂移**，建议只在长 history（>1024 tokens）时开。

   - 解决位置编码外推（让模型处理训练未见过的长位置）。不能解决"训练数据里没见过的内容能力"。
7. `--load_from ./model` 和 `--load_from ./minimind-3` 的区别？
   - 前者用 `model/` 下代码 + `out/` 下 `.pth`（PyTorch 原生）；后者用 `AutoModelForCausalLM.from_pretrained`（transformers 格式）。
8. minimind-3 在 4090 上推理大概多少 tokens/s？
   - 80-120 tokens/s（dense 64M bf16）。

</details>
