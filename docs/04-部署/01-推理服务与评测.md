## 步骤 0：前置 —— 把权重转成 transformers 格式

> `serve_openai_api.py`、`web_demo.py`、`vllm serve`、`ollama` **都需要 transformers 格式权重**（含 `config.json` + `model.safetensors` + tokenizer）。
> 你在 [02-实战](../02-实战/) 训练出来的是 `out/full_sft_768.pth` 这种**原生 torch** 权重，必须先转换。

`scripts/convert_model.py:128-134` 是默认入口，编辑 `__main__` 改路径后执行：

```bash
cd /path/to/minimind/scripts
python convert_model.py
```

默认会把 `../out/full_sft_768.pth` 转成 `../minimind-3/`（transformers 格式 + Qwen3 结构）。

关键函数 `convert_torch2transformers` (`scripts/convert_model.py:40`)：
- 用 `Qwen3ForCausalLM` / `Qwen3MoeForCausalLM` 作为目标结构（这就是 minimind-3 能直接被 vllm / ollama / transformers 原生加载的原因，见 [02-Transformer核心架构](../01-理论/02-Transformer核心架构.md) 的对齐表）
- 把 `MiniMindConfig` 的字段映射成 Qwen3 `common_config`，逐键 load_state_dict

✅ **验证**：`ls ../minimind-3/` 应能看到 `config.json`、`model.safetensors`、`tokenizer.json`、`tokenizer_config.json`。

## 步骤 1：启动 OpenAI 兼容 API 服务

`scripts/serve_openai_api.py` 是一个**纯 PyTorch + FastAPI** 的轻量服务，端点对齐 OpenAI `/v1/chat/completions`。

### 1.1 启动

```bash
# 用 transformers 格式权重（推荐，最省事）
cd /path/to/minimind/scripts
python serve_openai_api.py --load_from ../minimind-3

# 或用原生 torch 权重（你刚训完的那种）
python serve_openai_api.py --load_from ../model --weight full_sft --hidden_size 768 --num_hidden_layers 8
```

> `--load_from` 路径包含 `model` 字样时走 `MiniMindForCausalLM` 原生加载（`scripts/serve_openai_api.py:30-43`），否则走 `AutoModelForCausalLM.from_pretrained` (`:45`)。

启动成功后看到：
```
MiniMind模型参数量: 64.xx M(illion)
INFO:     Uvicorn running on http://0.0.0.0:8998
```

### 1.2 端点说明

| 路径 | 方法 | 用途 |
|---|---|---|
| `/v1/chat/completions` | POST | 聊天补全，支持 stream / 非 stream |

请求体 `ChatRequest` 定义在 `scripts/serve_openai_api.py:50-59`，比 OpenAI 多两个字段：
- `open_thinking: bool` —— 是否强制开启显式思考链（think 标签）
- `chat_template_kwargs: dict` —— 兼容 vllm / ollama 的写法，里面也能塞 `open_thinking`

响应解析 `parse_response` (`scripts/serve_openai_api.py:83-102`) 把模型输出拆成三部分：
1. `reasoning_content`：抽出 think 标签或裸前缀
2. `content`：去掉 think 后的正式回答
3. `tool_calls`：解析 JSON 形式的工具调用标签

流式输出还做了**思考 / 回答分阶段** delta 投递（`serve_openai_api.py:145-167`）—— 在思考标签闭合前发 `delta.reasoning_content`，之后发 `delta.content`，最后发 `delta.tool_calls` + `finish_reason`。

### 1.3 用 curl 测试

```bash
curl http://localhost:8998/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimind",
    "messages": [{"role": "user", "content": "世界上最高的山是什么？"}],
    "temperature": 0.7,
    "max_tokens": 512,
    "stream": true,
    "open_thinking": true
  }'
```

✅ **验证**：能看到 SSE 流式分片输出，开头是 `reasoning_content` 字段（思考），切到 `content` 字段（回答），最后 `finish_reason: "stop"`。

### 1.4 用 openai SDK 测试（推荐）

`scripts/chat_api.py` 是官方示例，把它改成指向你的服务：

```python

response = client.chat.completions.create(
    model="minimind",
    messages=[{"role": "user", "content": "你好"}],
    stream=True,
    extra_body={"chat_template_kwargs": {"open_thinking": True}},
)
for chunk in response:
    delta = chunk.choices[0].delta
    r = getattr(delta, 'reasoning_content', None) or ""
    if r: print(f'\033[90m{r}\033[0m', end="", flush=True)   # 灰色思考
    if delta.content: print(delta.content, end="", flush=True)
```

## 步骤 3：用 vllm 高性能推理

vllm 通过 **PagedAttention + 连续批处理** 把吞吐量拉到 PyTorch 原生的 5-10 倍，是生产部署首选。

```bash
pip install vllm
vllm serve /path/to/minimind-3 \
  --model-impl transformers \
  --served-model-name "minimind" \
  --port 8998
```

> `--model-impl transformers` 让 vllm 走 transformers 加载而非 vllm 原生（minimind 不是 vllm 内置模型）。
> ⚠️ vllm 需要 CUDA 环境，CPU 跑不了。

调用方式与步骤 1 完全一致（OpenAI SDK / curl）。

| 函数 | 位置 | 用途 |

## 步骤 8：跑 C-Eval / CMMLU / OpenBookQA 评测

主 README 在 `Ⅴ 客观评测`（README:1563）给出了 minimind-3 在 7 个数据集上的结果。

| 模型 | C-Eval | CMMLU | OpenBookQA |
|---|---|---|---|
| minimind-3 (64M) | 24.89 | 25.38 | 23.60 |
| minimind-3-moe (198M) | 25.48 | 24.32 | 26.20 |
| minimind-3-exam (64M + LoRA) | **30.98** | **26.12** | 24.20 |
| TinyLlama-1.1B | 25.71 | 25.03 | 35.60 |

> 数据来源 README:1591-1592。注意 minimind-3 数据偏中文，英文成绩普遍偏低，纯属"娱乐参考"。

### 8.1 安装 lm-evaluation-harness

```bash
git clone https://github.com/EleutherAI/lm-evaluation-harness
cd lm-evaluation-harness && pip install -e .
```

### 8.2 跑评测

```bash
# 单数据集示例
HF_ENDPOINT=https://hf-mirror.com lm_eval \
  --model hf \
  --model_args pretrained="/path/to/minimind-3",dtype=auto \
  --tasks ceval-valid \
  --batch_size 16 \
  --device cuda \
  --trust_remote_code \
  --apply_chat_template

# 多数据集一起跑
HF_ENDPOINT=https://hf-mirror.com lm_eval \
  --model hf \
  --model_args pretrained="/path/to/minimind-3",dtype=auto \
  --tasks "ceval-valid,cmmlu,openbookqa,hellaswag,piqa,arc_easy,social_iqa" \
  --batch_size 16 \
  --device cuda \
  --trust_remote_code \
  --apply_chat_template
```

> - `--apply_chat_template`：用模型的 chat template 包裹 prompt。**指令模型**（full_sft/dpo 等）要加；**基座模型**（pretrain）不加。
> - 评测原理不是让模型自由生成，而是**比较候选选项的条件概率**（README:1585），所以 mini 模型的分数常徘徊在随机基线附近 —— 别因此灰心。
> - 国内速度慢 → 加 `HF_ENDPOINT=https://hf-mirror.com`。

### 8.3 用 modelscope / OpenCompass（备选）

主 README 推荐 `lm-evaluation`；社区也常用 [OpenCompass](https://github.com/open-compass/opencompass)，配置更重但支持更多任务（含生成式评测）。`requirements.txt:30` 已包含 `modelscope==1.37.0`，可用 modelscope 的 [llm-eval 脚本](https://www.modelscope.cn/) 在线评测。

✅ **验证**：跑完后 `lm_eval --tasks ceval-valid` 会输出 `acc` / `acc_norm` 两列，与上表对照（±1% 浮动正常）。

## 步骤 9：性能优化速查

minimind 已经默认开启大多数优化，这里给出代码定位 + 调优建议：

| 优化项 | 状态 | 代码位置 | 调优建议 |
|---|---|---|---|
| **bf16/fp16 推理** | ✅ 默认 half | `serve_openai_api.py:47` `.half()` / `web_demo.py:208` | 想要 bf16 改成 `.to(torch.bfloat16)`；推理精度差异极小 |
| **KV cache** | ✅ 默认开启 | `model_minimind.py:120-122` / `:281` | `use_cache=True`，generate 时每步只算新 token |
| **Flash Attention** | ✅ 自动启用 | `model_minimind.py:125` `F.scaled_dot_product_attention` | PyTorch 2.x 自带，GPU 自动走 fused kernel |
| **GQA（省 KV）** | ✅ 内置 | `model_minimind.py:96-97` q=8/kv=4 | KV cache 显存比 MHA 省一半 |
| **tie embeddings** | ✅ 内置 | `model_minimind.py:242` | embedding/lm_head 共享，省 ~5M 参数 |
| **batch 推理** | ✅ 支持 | `eval_llm.py:82-87` / `serve_openai_api.py` uvicorn 多请求 | API 服务天然 batch（uvicorn 异步）；CLI 单条更直观 |
| **YaRN 长上下文外推** | ⚙️ 可选 | `serve_openai_api.py:247` `--inference_rope_scaling` | 训练 max_pos=2048 → 推理可扩到 32768，质量略降 |

## 🧯 踩坑提示

### Q1：`serve_openai_api.py` 启动报 `MiniMindConfig` 不识别
权重是 transformers 格式但缺 `model_minimind.py` 文件。重新跑 `convert_model.py` 转换，或把 `model/model_minimind.py` 复制到权重目录。

### Q2：WebUI 显示 "No models found"
`scripts/` 下没有含权重的子目录。**WebUI 只扫 `scripts/` 同级目录**（`web_demo.py:240-248`），不会递归或向上找。复制权重进去：`cp -r minimind-3 scripts/minimind-3`。

### Q3：curl 调用流式接口只收到一整块、不像 ChatGPT 那样逐字
检查请求体是否 `"stream": true`，以及 `accept: text/event-stream` 头。`serve_openai_api.py:182-192` 用 `StreamingResponse` 返回 SSE，curl 默认会缓冲，加 `-N` 关闭缓冲：`curl -N http://...`。

### Q4：vllm serve 报 "model architecture minimind not supported"
vllm 不识别 `model_type: "minimind"`。换成用 `convert_torch2transformers` 转出的 **Qwen3 结构**权重（`convert_model.py:40`），或在启动时加 `--model-impl transformers`。

### Q5：ollama 加载后回答是乱码
`minimind.modelfile` 的 `TEMPLATE` 没对齐 chat_template。直接抄主 README:1753-1808 的模板，**别自己写**。stop token 必须是 `<|im_start|>` 和 `<|im_end|>`。

### Q6：lm_eval 跑 OpenBookQA 分数只有 23% ≈ 随机
正常。minimind-3 训练数据偏中文 + 没做选择题格式对齐。主 README 给的 23.60 就是基线（README:1591）。想提分就用 `lora_exam` 数据做一次 LoRA + 合并 → `minimind-3-exam`，分数能涨到 24.20 / C-Eval 30.98。

### Q7：合并 LoRA 后跑 `eval_llm.py` 报 size mismatch
`convert_merge_base_lora` 输出的是 **base 结构**权重（不含 LoRA 的 A/B 矩阵），必须用 `--weight merge_identity` 之类的合并后文件名，**不要**再叠加 `--lora_weight lora_identity`。

### Q8：transformers 5.x 加载报 `rope_parameters` 未知
`convert_model.py:30-35` / `:90-95` 已有兼容写法，重新跑一次转换即可。该 patch 会把 `rope_parameters` 删除并改写 `rope_theta` / `rope_scaling`。

### Q9：API 调用思考链收到的是合并的 `reasoning_content`，不是流式
